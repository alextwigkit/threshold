# Edge — implementation plan

## 1. Consolidation
Preserve source images, record precedence, write product/UX/design/engine contracts. Do not reopen broad design exploration. Done when every known correction maps to a test or explicit UI behavior.

## 2. Coherent first slice
Scaffold mobile PWA and shared design tokens. Implement Name and editable Setup through the shared engine contract. Show the first meaningful local preview once the real first-use surface compiles. Avoid alternate screen-by-screen designs.

## 3. Complete local loop
Implement timestamp-based active session, progressive return, idempotent persistence, evidence-based observation and map projection. Add Atlas and Me. Use explicit local storage disclosure, export and deletion. Add manifest, offline shell, icons and installation guidance. No fake accounts or backend inference.

## 4. Verify and privately publish
Run production build and targeted engine/state tests. Verify served manifest and service worker. Private hosted preview if platform supports publication. Record browser/device QA honestly; physical iOS/Android install, offline restart, 200% text and screen-reader testing remain mandatory before public launch.

## 5. Production behavior engine
Add secure structured inference behind the existing interface, schema validation and fallback. Expand reviewed action templates. Evaluate recommendation relevance and claim accuracy with diverse situations. Tune provisional discovery thresholds from real longitudinal evidence.

## 6. Durable account and richer world
Add explicitly designed identity/sync and conflict handling without lengthening first use. Replace/extend simple map geometry with richer evidence-linked authored geography. Add inhabitants only when recurring behavioral moves have supporting evidence. Test actual repeated use before adding more game systems.

## Release gates
- All seven source screens have a corresponding coherent state.
- Prediction 0–10, progressive return, multi-select noticing, dynamic recommendation and emergent territory rules are verified.
- Every observation/discovery cites real stored evidence.
- Timer expiry and app visits cannot create progress.
- No lost data on reload, duplicate encounters or misleading saved state.
- Core loop works offline after initial load; installed presentation is usable.
- Visual and accessibility/device validation completed before calling this production-ready.

## Scope decision log
Device-local storage and deterministic routing are provisional first-build choices. They support a usable offline vertical slice without pretending the unfinished model engine or cross-device product already exists. Future implementation must preserve the same UX constraints.

## Completed continuation
Expanded reviewed action templates, independent multi-select discovery evidence, carried-discomfort discovery, stable evidence-driven map paths, territory-to-Atlas navigation and discovery marks. Added validated backup restore with merge preview, collision handling and draft/session preservation. Another-tab changes freeze saving and offer export/reload rather than silently overwriting local work.

Next: secure structured inference and evaluated action coverage; cross-device identity/sync; physical-device, accessibility and visual validation; authored inhabitants once repeated behavior supports them. A live model integration still requires a configured server-side provider and its consent/retention design; no user situations are transmitted by the current app.
